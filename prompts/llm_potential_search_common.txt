Design a potential function for potential-based reward shaping to improve the convergence speed of centralized TD3 movement control in the UAV data-collection system below.

Provide Python code defining compute_potential_components(obs, constants), together with each component's name, brief description, and fixed weight.

1. System operation and task objective

The system contains 16 UAVs, one ground station (GS), and 2–8 regions of interest (RoIs) in a standard 1000 × 1000 m disaster area.

UAV tasks are:
- Search: discover previously unknown RoIs.
- Visual sensing (VS): capture data from an assigned RoI.
- Communication collection (COM): receive data from an assigned ground source (SR).
- Hover: remain hovering.

A UAV may serve VS and COM simultaneously with different targets.

Task allocation assigns roles and service targets according to existing update rules. TD3 controls the UAVs identified by movement_mask. Each controlled UAV has three action components: speed, horizontal heading, and vertical speed. Existing controllers handle search and hovering behavior.

After movement updates positions and link conditions, the routing controller selects packet next hops.

A movement decision occurs every 1 s. Each interval contains four communication slots of 0.25 s. An episode lasts 60 s.

The execution sequence is:

current observations and task assignments
→ TD3 movement action
→ position and sensing/link updates
→ data acquisition, queueing, uploads, and relay transmissions
→ interval delivery, energy, and penalty calculation
→ next movement decision

Task allocation is updated when its existing rules trigger.

Data follows these paths:

VS: capturing UAV → zero or more relay UAVs → GS

COM: SR queue → serving UAV → zero or more relay UAVs → GS

Packet deadlines are measured from generation until GS delivery:
- VS: 0.015 s (15 ms).
- COM: 0.010 s (10 ms).

All UAVs preselect one physically legal next hop per 0.25 s routing slot and hold it for that slot. Fixed-interval traffic events are invisible before generation. Event-time, full-packet store-and-forward permits same-slot multi-hop S2U/U2U/U2G service. Dynamic equal FDMA includes only currently serviceable links, and 5 ms fading blocks do not impose a minimum hop time.

Changing a packet's current node does not restart its deadline.

The task objective is energy-efficient timely delivery:

EE = sum_t B_timely,t / sum_t E_movement,t

B_timely,t is useful data delivered to the GS within its deadline during interval t.
E_movement,t is the movement energy of all UAVs during interval t.

Data acquisition and intermediate forwarding contribute to the task through subsequent timely GS delivery. Consider useful delivery, movement energy, and end-to-end deadline violations together.

4. Potential and shaping construction

Implement:

compute_potential_components(obs, constants)

Return an unweighted one-dimensional numeric list or NumPy array:

f(s) = [f_0(s), ..., f_(K-1)(s)]
0 <= f_k(s) <= 1

Keep component order and normalization fixed across samples and episodes. Briefly explain each normalization scale in its description.

Assign a fixed finite weight w_k to each component. Weights may be positive, negative, or zero. Their sum and absolute sum are unrestricted.

The host computes:

Phi(s) = sum_k w_k * f_k(s)

F_t = beta * [gamma * Phi(s_next) - Phi(s_current)]

r_train,t = r_base,t + F_t

gamma = {{GAMMA}}
beta = {{BETA}}

gamma is the same discount factor used by TD3.

The contribution of component k is:

F_t,k = beta * w_k * [gamma * f_k(s_next) - f_k(s_current)]

For gamma = 1, a component's contribution depends on its change between consecutive states. Positive weights reward increases; negative weights reward decreases.

For other gamma values, use the full discounted expression when interpreting the contribution.
