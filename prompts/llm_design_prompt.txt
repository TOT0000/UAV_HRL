Design additional state features and fixed reward weights for centralized TD3 movement control in the UAV data-collection system below.

Provide:

1. System operation and objective

The system contains 16 UAVs, one ground station (GS), and 2-8 regions of interest (RoIs) in a standard 1000 x 1000 m disaster area.

UAV tasks are Search (discover unknown RoIs), visual sensing (VS, capture an assigned RoI), communication collection (COM, receive data from an assigned ground source/SR), and Hover. A UAV may serve VS and COM simultaneously with different targets. Task allocation assigns roles and targets; TD3 controls UAVs identified by movement_mask; existing controllers handle Search and Hover; and a separate routing controller chooses packet next hops after movement.

A movement decision occurs every 1 s. Each interval contains four communication slots of 0.25 s. An episode lasts 60 s. Task allocation changes only when its existing rules trigger. TD3 changes positions, not assignments, next hops, or scheduling.

The execution sequence is:
current observations and task assignments
-> TD3 movement action
-> position and sensing/link updates
-> data acquisition, queueing, uploads, and relay transmissions
-> interval delivery, energy, and penalty calculation
-> next movement decision

VS data follows capturing UAV -> zero or more relay UAVs -> GS. COM data follows SR queue -> serving UAV -> zero or more relay UAVs -> GS. Deadlines run from generation through GS delivery and do not restart at a relay: VS 2.5 s; COM 2.0 s.

The task seeks higher energy efficiency and fewer end-to-end deadline violations:

EE = sum_t B_timely,t / sum_t E_movement,t

B_timely,t is useful data delivered to the GS within deadline during interval t. E_movement,t is movement energy of all UAVs during interval t. The ratio uses episode totals; acquisition and intermediate forwarding are not GS delivery.

4. Feature and reward construction

Choose K and implement compute_extra_state(obs, constants). Return an unweighted one-dimensional numeric list or NumPy array f=[f_0,...,f_(K-1)] with 0 <= f_k <= 1. Keep order and normalization fixed, and state the normalization and empty-input behavior briefly in each description.

Assign each feature a fixed finite reward_weight w_k. Positive weights reward larger values, negative weights penalize them, and zero adds state without direct reward. There is no restriction on the sum or absolute sum of weights. The host does not normalize weights.

s_aug = concat(s_original, f)
r_extra = sum_k w_k * f_k
r_total = r_base + beta * r_extra

r_base = B_timely_Mbit - lambda * E_movement_J - P_C9 - P_C10 - P_COM

B_timely_Mbit and E_movement_J are subsequent-interval outcomes in Mbit and J; lambda is training-managed. beta = {{BETA}}. Features are computed before action, so r_extra is current-state information while r_base contains subsequent outcomes. r_extra and r_total are not restricted to [-1,1]. Every numeric value must remain finite.
