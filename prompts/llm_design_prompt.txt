Design additional state features and fixed reward weights for the centralized TD3 movement controller in the UAV data-collection system below.

Provide:
1. Python function compute_extra_state(obs, constants).
2. Each feature's name, brief description, and reward_weight.

1. System, workflow, and objective

The system contains 16 UAVs, one ground station (GS), and 2-8 regions of interest (RoIs) in a standard 1000 x 1000 m area.

UAV tasks:
- Search: explore and discover RoIs.
- VS: capture an assigned RoI and generate visual data.
- COM: receive data from an assigned ground source (SR).
- Hover: remain hovering.

A UAV may perform VS and COM simultaneously for different targets.

Control responsibilities:
- Task allocation: determines tasks and targets under existing update rules.
- TD3: controls horizontal speed, heading, and vertical speed for UAVs identified by movement_mask.
- Routing: selects packet next hops.
- Search and Hover: handled by existing controllers.

Each episode lasts 60 s. TD3 acts every 1 s, with four 0.25 s communication slots per interval.

Execution sequence:
current observations and task assignments
-> TD3 movement
-> position, sensing, and link updates
-> data acquisition, queueing, and transmission
-> interval delivery, energy, and penalty calculation
-> next observation.

Data paths:
VS: sensing UAV -> zero or more relay UAVs -> GS.
COM: SR queue -> serving UAV -> zero or more relay UAVs -> GS.

Packet deadlines run from generation until GS delivery: 2.5 s for VS and 2.0 s for COM.

The objective is higher energy efficiency and fewer end-to-end deadline violations:

EE = sum_t B_timely,t / sum_t E_movement,t

B_timely,t: useful data delivered to the GS within deadline during interval t.
E_movement,t: movement energy of all UAVs during interval t.
The sums cover the entire episode.

4. Feature and reward structure

Choose the number of features K. Return an unweighted one-dimensional numeric list or NumPy array:

f = [f_0, ..., f_(K-1)]
0 <= f_k <= 1

Keep feature order and normalization fixed across samples and episodes.

Assign each feature a fixed finite weight w_k:
- Positive: rewards larger feature values.
- Negative: penalizes larger feature values.
- Zero: provides state information only.

There is no restriction on the sum or absolute sum of weights.

The host computes:

s_aug = concat(s_original, f)
r_extra = sum_k w_k * f_k
r_total = r_base + beta * r_extra

r_base =
B_timely_Mbit - lambda * E_movement_J
- P_C9 - P_C10 - P_COM

The original state is preserved.
B_timely_Mbit, E_movement_J, and penalties are subsequent-interval outcomes.
lambda is managed by training.
beta = {{BETA}}

f and r_extra use pre-action information.
r_extra and r_total may exceed [-1,1]; all results must remain finite.
