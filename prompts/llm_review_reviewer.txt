Review requirements

1. Implementation and description

Check whether each feature's code computes what its name and description claim. Look for clear errors in data selection, validity handling, and normalization.

2. Reward direction

Read each feature formula together with its weight to determine which conditions receive a higher reward contribution.

Check whether this agrees with the stated purpose and whether it creates a clear conflict with timely delivery, movement-energy efficiency, or end-to-end deadlines.

3. Necessary changes

For each issue, identify the affected feature or computation, explain the problem, and propose an implementable change using the available inputs and supported operations.

Changes may include adding, removing, or modifying features, changing normalization, or adjusting weights.

Support findings with the code, system definitions, or supplied validation evidence. Label uncertain effects as possible risks.

If previous suggestions are provided, check whether they have been addressed.

When no issue requiring revision is found, return needs_revision=false. This review assesses the design before training; improved training performance remains unverified.
