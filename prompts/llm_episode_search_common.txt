You design additional state features and fixed reward weights for centralized TD3 movement control in the UAV data-collection system below.

1. System operation and objective

The system contains 16 UAVs, one ground station (GS), and 2–8 regions of interest (RoIs) in a standard 1000 × 1000 m disaster area.

UAV tasks are:
- Search: discover previously unknown RoIs.
- Visual sensing (VS): capture data from an assigned RoI.
- Communication collection (COM): receive data from an assigned ground source (SR).
- Hover: remain hovering.

A UAV may serve VS and COM simultaneously with different targets.

The system has three control functions:
- Task allocation assigns UAV roles and service targets.
- TD3 controls movement for UAVs identified by movement_mask. Each controlled UAV has speed, horizontal-heading, and vertical-speed action components. Existing controllers handle search and hovering.
- After movement updates positions and links, the routing controller selects packet next hops during communication slots.

A movement decision occurs every 1 s. Each interval contains four communication slots of 0.25 s. An episode lasts 60 s.

The sequence is:
current observations and task assignments
→ TD3 movement action
→ position and sensing/link updates
→ data acquisition, queueing, uploads, and relay transmissions
→ interval delivery, energy, and penalty calculation
→ next movement decision.

Task allocation changes when its existing update rules trigger. TD3 changes positions; task assignments, next hops, and scheduling are controlled by the existing mechanisms.

Data paths:
VS: capturing UAV → zero or more relay UAVs → GS.
COM: SR queue → serving UAV → zero or more relay UAVs → GS.

Packet deadlines are measured from generation until GS delivery:
- VS: 2.5 s.
- COM: 2.0 s.

Moving a packet to another UAV does not restart its deadline.

The primary objective is episode energy efficiency:

EE = sum_t B_timely,t / sum_t E_movement,t

B_timely,t is useful data delivered to the GS within its deadline. E_movement,t is movement energy of all UAVs. Acquisition and intermediate forwarding contribute to the task when the data subsequently reaches the GS on time.

The system also tracks end-to-end deadline violations. Interpret these together with useful delivery volume and energy use.

For capacity C_ab in bits/s and a 0.25 s slot, constant-capacity service satisfies B_ab <= C_ab * 0.25.

Relay connectivity requires a sequence of valid directed links to the GS. Path service also depends on capacity and waiting time.

remaining_deadline_p = deadline_p - (current_time - generation_time_p).

End-to-end delay includes source waiting, UAV queueing, scheduling, and subsequent transmissions.

6. Candidate evaluation

The host first checks execution and numeric validity. For each complete recorded episode i:

EE_i = sum_t B_timely_i,t / sum_t E_movement_i,t
G_i = sum_t r_total_i,t

G_i is undiscounted. The pre-training score measures whether higher-EE episodes receive higher G_i.

{{RANKING_EVALUATION_SPEC}}

All candidates and the baseline use the same episodes and fixed evaluation lambda. Actual training retains the original lambda update procedure.

Pretraining selection:
All candidates are evaluated using the same episode dataset and scoring settings. The acceptance threshold is the highest ranking consistency achieved by the original reward or any candidate previously sent for training in this search. A new candidate must strictly exceed this threshold to be eligible for training. Among eligible candidates in the current batch, the host selects the one with the highest ranking consistency.

Revision reference:
The candidate used as the design reference is the one with the best historical mean evaluation EE. This candidate may differ from the candidate defining the pretraining threshold. Use the supplied training and evaluation feedback to revise the design while aiming to exceed the current pretraining threshold.

Selected candidates are trained for 1500 episodes and evaluated on 100 shared scenarios with 8 RoIs in a 1000 × 1000 m area. Mean episode EE determines the best trained candidate.

Pre-training ordering is a screening measure. Training and evaluation determine observed policy performance.
